# 校园水务知识总览

本文是校园水务 RAG 的跨主题索引，帮助回答需要组合多个知识域的问题。它不替代实时业务数据、现场图纸、设备说明书或正式安全规程；涉及告警确认、阀门操作、水质结论和报修派单时必须由值班人员复核。

## 问题分类与数据边界

校园水务问题通常分为用水统计、计量与设备、漏损与异常、水质与排水、模型分析与调度。历史统计可以从经过校验的水表数据计算，实时状态必须调用业务接口。知识库只能说明指标含义、排查方法和分析步骤，不能凭空给出某个校区当前读数、设备在线状态或水质是否合格。回答前先确认校区、楼宇或设备编码、时间范围、指标口径和用户希望的输出；累计量、瞬时流量、日用水量和同比环比不能混用。

## 计量链路与设备排查

典型链路为“水表/传感器—RS485 或无线链路—网关—网络—平台—报表”。单台设备离线，先核对最后一次上报时间、供电、阀门和通信指示灯，再检查地址、串口参数、信号强度及网关缓存。多台设备同时离线，优先检查共同网关、交换机、网络或平台服务，不应逐台更换设备。恢复通信后要核对断点补传、时间戳、累计量连续性和重复数据。设备编码只能定位设备，不代表设备一定属于该位置；迁移、换表和资产变更必须以资产台账为准。

## 用水平衡、漏损与异常

分区水平衡可写成：总表进水量 = 分表计量量 + 合理未计量量 + 漏损量。合理未计量量包括消防试水、绿化取水、施工临时用水和表计误差，不能直接当作漏水。夜间最小流量持续偏高时，结合宿舍、食堂、实验室和绿化用水日历判断；短时尖峰不等于爆管，需看持续时间、压力变化、相邻表计和现场巡检结果。基线分析应先处理缺失、重复、回退、负值和异常间隔，再计算均值、分位数和偏差。

## 水质、雨洪与模型

水质监测应记录采样点、时间、人员、仪器校准、样品保存和复测结果。pH、电导率、浊度、余氯异常首先排除传感器污染、温度影响和采样流程问题，不能凭单点读数宣布水质不合格。降雨—产流分析需要明确汇水区、不透水率、下垫面、管网节点和降雨序列。SWMM 模型应检查子汇水区、节点、管段、出口、蓄水单元、泵和孔口/堰，以及时间步长、初损、糙率和边界条件。模型输出先做质量审查，再用于方案比较，不能直接触发现场操作。

## 调度、节水与 RAG 回答规范

水库或蓄水单元调度要考虑需求预测、库容上下限、供水安全、泵组能力、峰谷电价和降雨不确定性。宿舍重点关注夜间小流量和分区计量，食堂关注营业时段峰值，实验室关注特殊工艺用水，绿化关注天气和灌溉窗口，场馆关注活动日程。RAG 回答应优先引用相关主题文档，再用本总览补充跨主题定义；资料未覆盖时明确说明“知识库未找到”，并列出需要的实时数据或现场信息。关阀、改参数、派单、删除数据等写操作必须先展示影响范围和风险并获得明确确认。

## 常用排查顺序

1. 明确对象、时间、指标和问题类型。
2. 检查数据是否完整、连续、去重且单位一致。
3. 沿计量链路定位是表计、通信、平台还是业务口径问题。
4. 结合天气、日历、维修和现场信息交叉验证。
5. 给出证据、置信度、下一步和人工复核要求，不把推测写成事实。
